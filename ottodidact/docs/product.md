# Current product behavior

The Windows capture/overlay/branch workflow is preserved. The new backend supports real image questions and followups; explicit mock mode remains for offline demos. The real provider needs a backend API key and a compatible configured model.

Each activation dims the screen immediately, then takes one full-display snapshot with the protected dimming surface excluded. The user marks a focus rectangle on that frozen image and uses the compact Ask Otto panel beside that rectangle. The gold Quick answer button answers the selected content directly, independently of any typed draft. The dark send arrow and Enter submit the typed question; Shift+Enter adds a newline. Failed requests preserve the draft. Full-screen context is always included; Hint/Explain and connection information are secondary settings. Answers are based on that captured instant. Math is rendered safely. Annotations appear only after structured output passes validation, with text-only answers allowed when locations cannot be identified.

Each annotation owns a stable conversation tied to the original capture. Numbered branches open in movable native windows and resume without duplication. They share lesson context automatically while keeping visible messages separate; no bring-back action is needed. New capture replaces the temporary session; cancellation ignores obsolete responses. Clear annotations retains branch chats.

The launcher selects directly and has no secondary strip. The main-chat gear opens inline settings for Always on / Only when needed. Right-click Otto or Ctrl+Shift+M restores main chat; pending question drafts survive this switch. The body starts 16 logical pixels from the usable bottom-right corner, and dragged positions persist. Neither monitors the screen. A stationary pulsing Otto face marks the selected region during processing. The explanation dims surrounding content, leaving the selected region and panels readable. Dismiss restores the chosen idle glow. Loading, cancel, retry, setup errors, and explicit demo labels are visible. No automatic paid retries or fallback answers are used. Only requested snapshots are uploaded; no continuous screen awareness is claimed.

The supplied UI boards guide the warm ivory surfaces, multicolor glass two-eye Otto mark, color-coded cards and compact composers. Cards appear with the explanation, each already offering an input. Sending expands the same native chat; collapse and close retain its history. Colored curved connectors follow card movement while their targets remain fixed to the captured snapshot. The main chat uses matching numbered chips. Screen material always comes from the actual selected desktop; the projectile worksheet in the design board is not embedded into the app.

Main chat defaults above Otto and grows upward. It automatically avoids the focus where readable space exists, stays stable on ordinary messages and branch-open events, and follows Otto between corners. Tight layouts have minimize/restore; drafts and reading position stay in place. Long chats scroll internally and follow replies only when already near the bottom. Dismiss resets the default anchor.

Selection responds immediately, even while its snapshot is being prepared. A deliberate 6-by-6 logical-pixel drag is accepted in either direction; clicks stay in selection mode. Escape cancels the activation, obsolete results are ignored and native captures run serially. The button colors keep moving in both availability modes; its exterior halo follows the edge glow mode, with reduced motion and hidden-window animation handling.

The screen edge and glass launcher share a 24-second animation clock and palette. Independent gold, orange/red and smaller blue pools move, stretch and exchange positions across the entire globe, without contour lines. The screen has two separated drifting blue/cyan accents. A narrow luminous source and saturated surrounding light fade into transparency. Otto's wider halo extends beyond its small input window on the click-through decoration layer, with a diffuse bottom falloff that can overlap the edge illumination; the round body remains separate. Reflections and internal shading give the sphere depth. Brightness does not pulse; reduced motion freezes both at the same phase. The material does not darken the desktop; lesson dimming remains a separate existing feature.

Both the question panel and main chat have a compact header with the accepted logo, Otto name, functional settings gear, and appropriate retake/minimize/close controls. Settings open in the same window, retain drafts and reading position, and close with Escape. The separate Quick answer action still works without typing.

The launcher and miniature chat-header glass emblems have the same eyes, with small glances and occasional blinks separated by varied quiet pauses. This is decorative only; hidden emblems pause, and reduced motion keeps open, stationary eyes. When nearly full-screen focus leaves no free readable space, main chat reduces to 300 x 300 DIPs with internal scrolling and minimize/restore.

The latest factoring reference defines the presentation: ivory panels, a compact glass-logo header, lavender user bubbles and warm assistant bubbles, square dark send controls, serif explanation cards with amber/blue identities, and quiet focus brackets. Cards prefer a vertical rail beside the focus. Their leaders end on the referenced shape, with arrowheads and a small source dot. Main-chat secondary tools and snapshot details live in the functional settings panel. Native reference screenshots use a separate generated worksheet and predetermined response strictly within the opt-in smoke harness; production still captures the real desktop and labels mock content.
