# Real tutor milestone architecture

Sandboxed Electron windows for the launcher, selection, annotations, effects, settings, main chat and lazily created branch chats share one authoritative main-process Session over validated, role-restricted IPC. The renderer never calls a model or handles credentials. Electron calls a separate loopback HTTP backend. That backend alone loads .env and contacts the configured provider.

Capture hides Otto controls and shows the protected selection window immediately. A dimming layer sits above its frozen image and is replaced by a clear rectangle while dragging. Windows capture exclusion keeps this visible surface out of the full-display capture; unsupported OS versions briefly hide it instead. The bounded full-display PNG is both the frozen selection background sent as full-screen context to the backend. Initial explanations may additionally include one bounded focus close-up derived from that exact saved PNG (maximum 1536 pixels per edge / 768 KiB); followups omit it. It is not another screen capture or a per-character provider request. Focus is quantized to that exact transmitted image. Global display origins are applied only to native window bounds; screenshot/annotation coordinates stay display-local. `desktop/displays.ts` tracks the active monitor, and full-size decoration uses its full bounds, including the taskbar. Selection renders the same edge-glow component above the frozen image so it cannot obscure the glow. The question panel is placed adjacent to the focus with work-area clamping with compact Retake/Close and a separate Quick answer action. Geometry changes abort pending requests and dismiss obsolete targets while retaining lesson text; a new capture requires no restart.

shared/ai.ts defines runtime-validated request, response, and normalized annotation schemas. The backend asks for a strict structured explanation and independently rejects malformed output. shared/annotationMapping.ts maps normalized target rectangles through the exact input image's desktop rectangle; arrow endpoints, circles, underlines, highlights, and clamped explanation bubbles with target connectors are rendered on the native overlay.

desktop/tutor.ts binds requests to session, capture, conversation, and request IDs. A single AbortController prevents duplicate submission and cancels obsolete work. Every completion checks identity before mutation, so late results cannot modify a new capture. Failed or cancelled requests keep explicit retry state without fabricating a response.

Branches keep their original question, explanation, annotation, image, and messages. buildTutorRequest serializes the active history and shared/lessonContext.ts selects bounded related discussions by visible box number, title or recency. Related messages are context only: they never enter another visible transcript. Stable numbered annotations remain in lessonAnnotations after Clear, and each branch window is keyed by conversation ID so closing/moving/reopening retains identity. A successful new capture destroys old branch windows and resets lesson state. The backend is stateless for images/conversations and receives only the relevant snapshot on each request. It trims the text budget and never relies on a remote conversation that might contain another screenshot.

The provider adapter supports OpenAI Responses and a deterministic mock. OpenAI sends the full snapshot, optionally one initial focus close-up, and the bounded shared lesson context with high image detail, strict JSON schema, store:false and abortable HTTP. Complete shared validation rejects invalid coordinates, duplicate IDs and malformed results before rendering. Existing AbortSignal/deadline and explicit Retry own cancellation and retries; there are no automatic paid retries or mock fallbacks. Responses and usage logs record the actual returned model and available token counts, including usage on invalid/refused/incomplete output. Private input, credentials and upstream error bodies are never logged.

`server/ai/responsePolicy.ts` derives advisory task/style preferences without another model call. The original lesson intent and focus (causal, procedural or feature-specific) travel with local followups. Why inquiries take precedence over incidental solve keywords. Main supplies a complete structured answer; each initial card connects its source feature to a reason or step in that answer. Box followups answer the new question without restarting the lesson. There is no sentence quota or separate small-chat output cap; both surfaces use the configured maximum unless explicit brevity lowers it. Initial explanations use the full annotation schema; followups use only explanation, empty annotations and warnings, without the lengthy localization instructions. The model generates main and box text in one response, with no per-card review/summarization calls or text clipping.

Initial request assembly sets `originalQuestion` from the submitted inquiry instead of the not-yet-updated session, and clears any earlier main answer. Branch creation saves the original mode as well as question/main explanation/image/annotation. Lazy renderer loading only reads this saved record; it does not generate another answer or substitute a generic term prompt. For local followups, context allocation reserves active branch history before main reasoning and optional related history. OpenAI input consists of the snapshot/background, ordered active user/assistant messages, then the exact latest followup as the final user message. Original reasoning has an explicit shortening flag when a resource limit prevents including it all. Fixed branch context and visible transcripts are not mutated by this trimming. Unreferenced sibling histories are omitted for a local question; explicit number/title references still retrieve them, and main chat retains its recent-thread fallback. Duplicate initial main turns are omitted from shared history. There is no answer cache, automatic retry chain, or per-message summarization call.

The shared safe `MathText` renderer handles headings and comparison tables as escaped React elements, in addition to prose, bold, lists, KaTeX and code. Table parsing ignores pipes inside math/code and escaped pipes; model HTML remains inert. Stream previews and committed text take the same rendering path. Table wrapping and heading styles participate in the existing content measurement, without changing card sizing or routing.

Chat requests accept bounded SSE progress end to end. `shared/stream.ts` handles split frames, cancellation, JSON string escapes and partial Unicode; only explanation text is previewed. Backend validation still owns the complete result. A lightweight, read-only preload event sends progress only to the active conversation window, guarded by session/request/conversation IDs, without broadcasting images per token. Renderer previews are transient, safely formatted and removed on completion/error/cancel; shared histories change only on a valid final response. Existing scroll anchors apply during growth. Initial annotations never render from partial geometry.

Completed local image preparation is retained before sending the initial request, so an explicit retry after a provider error can reuse it. A stale or cancelled preparation cannot enter session state. Followups send the canonical full snapshot once and omit the detail crop. Active main history omits the initial question/answer already supplied in dedicated fields; bounded relevant threads remain separate context. Numerical timing events distinguish image preparation/validation, context, provider, first preview, parsing, state application and native card readiness. They do not establish real-model latency from mock tests.

The needed branch renderers are created hidden together instead of loading serially per explanation. Their measured reveal remains sequential; each card rechecks current peer bounds before showing. This overlaps renderer startup without changing chat identity, remounting a conversation, or giving unvalidated annotations early visibility. Capture/dismiss visibility versions and destroyed-window guards still suppress stale shows. The route planner evaluates four sides with straight, cubic and rounded candidates, rejecting tight local reversals; rounded candidates end directly at the saved tip instead of adding a compulsory final approach hook. Collision checks sample the actual curves against known feature and panel geometry.

Local HTTP access rejects browser origins and remote Host headers, limits body/image/context sizes, rate-limits requests, and rejects duplicate IDs. It has no authentication and must not be exposed publicly without user quotas and access control. Neither backend .env nor provider code/secrets are included in the Electron builder whitelist.

shared/appearance.ts derives idle/active/suspended glow, dimming and processing states. A separate non-focusable effects window always ignores native mouse input and stays beneath interactive windows. Capture suspends effects and hides controls, while the protected selection surface provides immediate feedback during the compositor delay. Only appearance.json is written to disk; it contains the validated glow mode and deliberately dragged launcher coordinates. Reduced-motion CSS disables rotation and pulse. All views subscribe to authoritative session updates; branch IPC cannot send, retry or cancel another chat's request.

shared/presentation.ts assigns stable colors and places compact native cards outside the selection and main panel where space allows. Electron publishes card bounds and visibility on native window events, allowing the annotation renderer to route arrow connectors without moving screenshot targets. Underline/circle/rectangle cards have no automatic connector. Annotation chats are initialized with an empty transcript when the explanation arrives, shown without taking focus, and expanded when requested, used, or required to scroll oversized initial content. Normalized model coordinates and backend context logic are unchanged by the presentation layer.

Main-chat placement uses global DIP rectangles in shared/presentation.ts. During a capture it prefers a left/right side strip outside the selected focus; otherwise the anchor is the actual launcher face. The measured main rectangle is reserved before card placement. shared/panelLayout.ts reflows visible measured cards together after content/size, movement, collapse/restore or main geometry changes. A 140 ms settle delay coalesces native events; moving windows does not steal focus, and valid positions remain stable. A requested/focused card retains priority across automatic resize notifications. Long conversations use a smaller readable scrolling viewport when necessary; peers fall back to their measured compact headers if they cannot fit. In nearly full-screen selections only the deliberately restored card may need to cover part of the focus. Renderer trees remain mounted, retaining drafts and reading anchors. Collapse differs from hiding history or dismissing the window. Marker restore reopens the same branch without a tutor call. Mini-chat submission updates expansion state without awaiting native show/measurement work before starting HTTP.

Selection starts accepting pointer input before the snapshot arrives. Pointer capture and animation-frame updates stay in the selection renderer. A completed rectangle waits locally for its snapshot; its activation ID must match the current desktop selection before IPC can commit it. desktop/captureQueue.ts serializes native capture tasks and suppresses stale successes and failures, including a cancellation followed immediately by replacement. The full image is captured once and focus is quantized to that image; no cropped-only context or continuous monitoring is introduced.

Snapshot encoding is isolated in a hidden sandboxed renderer, loaded from capture-encoder.html. Its separate preload accepts raw BGRA pixel jobs only from main and returns bounded PNG results through sender-validated IPC. Chromium OffscreenCanvas handles resizing and compression away from both the main event loop and selection UI; it has no lesson state or provider credentials. CaptureQueue still serializes the entire acquisition/encoding operation. A failed encoder can be recreated on Retake.

Selection pointer frames update four solid neutral dim rectangles and a thin outline directly, without session broadcasts or React rerenders. The selected focus then displays the exact frozen image through the question/explanation stages. A cached rotating color texture sits underneath the fixed screen-edge mask; Otto's face surface also changes color. Selection background throttling is disabled to avoid a first-use stall; hidden animations stop.

Targets may be null when the provider cannot locate a concept reliably. Those cards retain stable numbers and their conversations without overlay targets or connectors. Targets outside the focus are suppressed unless the question explicitly requests outside content; geometric clamping never invents a pointer. This check does not establish semantic model accuracy. There is no browser DOM or beyond-viewport text integration.

Ambient lighting is defined in shared/ambientLight.ts. Edge textures use compositor rotation synchronized to the shared 24-second clock on mount and visibility changes. LiquidGlass renders the globe with that clock, capped at 30 frames/second (20 for small emblems) and 2x backing resolution. No frame IPC or session broadcasts occur. A read-only, sender-checked appearance bridge supplies native geometry on movement. Reduced motion draws phase zero once; hidden globes stop their frame loop.

The compact 108-DIP launcher avoids fractional rounding at the tested Windows scale and gives the 76-DIP face a 16-DIP inset. Preferences retain valid deliberate placements across restarts. MainPanel hosts the settings component in its existing frame while its chat body remains mounted. Right-click/Ctrl+Shift+M restores main; a hidden question view retains its draft until Return to question. Main layout uses the actual face bounds and keeps existing focus avoidance.

The globe uses a small dependency-free WebGL fragment shader in src/components/liquidMaterial.ts. Independent gold, red and blue pools change position, radius and shape across the entire face on the existing 24-second clock. Smooth domain deformation replaces the earlier contour/caustic lines; this is a procedural material, not a physical fluid simulation. Curved transmission, directional sphere shading, soft elliptical reflections and a narrow almost-white rim provide depth. Interior color motion is independent of availability mode; only exterior lighting changes with that mode. Lighting is converted to display color before premultiplying alpha. Body, rim and scattered outer light have separate coverage; zero-alpha pixels contain zero RGB. There is no opaque bloom framebuffer or full-component opacity trick.

The body fits the existing 108-DIP launcher and 76-DIP face. A separate 320-DIP canvas draws only its wider halo in the existing full-display, non-focusable, click-through effects window; the small input window no longer clips that light. A read-only geometry/visibility event, available only to companion/effects windows, keeps the two draws aligned during dragging and display changes. The external halo mounts only while the native launcher is visible; selection never mounts it. Both share shader time and pigment. Screen lighting has a three-DIP core and a 36-DIP inward fade, with two separated blue/cyan pools. There is no circular cutout in the screen-edge light. The halo keeps the side core separate while a wider transparent bottom falloff overlaps the existing inward illumination. The round body stays separate. No desktop darkening is used to strengthen this material. The same shader renders the header emblem. Context loss reveals the existing CSS fallback; restoration recreates GPU resources. Visibility, reduced motion and prop changes preserve one context and the mounted eyes. Cleanup releases buffers, programs and the context. Main and question surfaces retain `ChatHeader` and the existing inline settings lifecycle and composers.

`useEmblemMotion` pauses decorative globe/eye CSS animations through document visibility and intersection observation, including mounted but hidden chat surfaces. Glance and blink tracks contain long quiet intervals and use different periods. Reduced-motion CSS removes both, leaving open eyes. Nearly full-screen focus adds a compact readable layout candidate without changing the screenshot, launcher, conversation or renderer instance.

CARD_SIZE is only a hidden-window fallback. useBranchLayout measures inert copies of the actual rendered card at bounded readable widths, including formatted prose, title wrapping, controls and history. A validated branchLayout command passes these dimensions to main; placeMeasuredCard retains a valid existing position or scores placements against the focus, main chat and actual other card bounds. Fractional-scale rounding and stable scrollbar gutters prevent a one-pixel overflow from changing text wrapping. Native changes publish connector origins without altering screenshot targets. Minimize, chat collapse and close retain the same mounted conversation and draft; content exceeding the work area uses an expanded scroll body. Safe formatting extends the existing KaTeX renderer with escaped paragraphs, lists, emphasis and code, with no HTML injection or new rendering dependency.

Snapshot, dimming, target markings and connectors are composed in the same click-through effects window, with graphics above the image. The separate annotation window supplies only interactive hit targets. This prevents native z-order changes from putting the frozen focus image over a pointer. Visible full-display windows disable background throttling so Windows transparent-window occlusion does not leave a stale frame; hiding them restores throttling and native visibility notifications. Hidden decorative animations still stop. shared/annotationOrganization.ts plans visibility and arrow routes together. Arrow tips remain fixed at their saved feature boundaries, independent of card placement; moving a card never changes its screenshot target. Primaries are prioritized before optional secondary details. Owner-checked hover/focus IPC updates decoration across windows without mutating messages; late blur/mouseleave events cannot clear another window's emphasis. Native hit testing and both renderer surfaces use the same plan, so hidden targets do not intercept desktop clicks. Main-panel bounds are published for routing avoidance. The measured card solver considers neighboring target/card order and route penalties while retaining valid existing positions. Main settings hold secondary screen controls and snapshot inspection while the conversation stays mounted. desktop/annotationReview.ts checks generated known targets and content sizes through actual native compositor pixels; desktop/referenceReview.ts provides the generated worksheet fixture. Both are opt-in and isolated from real providers.
